# Configuration

Cue is configured through a `config.yml` file that lives alongside the Docker container on each Pi. The Ansible playbook generates this file from a Jinja2 template using variables defined in your Semaphore inventory and environment.

## Full example

```yaml
tv_id: "tv-unknown"
api_key: "changeme"
pi_hdmi_port: 2
content_hdmi_port: 1
api_port: 5000
on_delay: 1
input_delay: 3
off_delay: 2  
```

## Reference

### `tv_id`

**Type:** string
**Default:** `tv-unknown`

A friendly label for this Pi and display. Appears in the `/health` endpoint response. Useful for identifying which Pi you are talking to when managing multiple devices.

---

### `api_key`

**Type:** string
**Default:** `changeme`

Required on all API requests via the `X-API-Key` header. Requests with a missing or incorrect key are rejected with a `401 Unauthorized` response.

Generate a secure key with:

```bash
openssl rand -hex 32
```

Set this as a secret in Semaphore rather than hardcoding it in your inventory. See [Semaphore](./semaphore) for details.

---

### `pi_hdmi_port`

**Type:** integer
**Default:** `2`

The TV's HDMI port the Pi is plugged into. Used internally to understand the Pi's position on the CEC bus. Run `echo "scan" | cec-client -s -d 1` to find the Pi's physical address — the first digit corresponds to the port number.

---

### `content_hdmi_port`

**Type:** integer
**Default:** `1`

The HDMI port the content source (laptop, media player, etc.) is connected to. The `on` command switches the display to this input after powering on.

---

### `api_port`

**Type:** integer
**Default:** `5000`

The port the Cue REST API listens on. Update this if port 5000 conflicts with something else on your network, and make sure to update your firewall rules and Director config accordingly.

---

### `on_delay`

**Type:** integer (seconds)
**Default:** `1`

How long to wait between sending the power on command and asserting the Pi as the active source. Increase this if the display is slow to respond after waking.

---

### `input_delay`

**Type:** integer (seconds)
**Default:** `3`

How long to wait after asserting the active source before switching to the content input. This gives the display time to register the wake before the input switch is sent.

---

### `off_delay`

**Type:** integer (seconds)
**Default:** `2`

How long to wait between asserting the Pi as the active source and sending the standby command. Some displays need a moment after an input change before they will accept a standby command.

---

### `bus_wait_timeout`

**Type:** integer (seconds)
**Default:** `15`

How long the `on` sequence will wait for the CEC bus to become ready before sending the content input switch. If the display does not come online within this window, the input switch is sent anyway with a warning in the logs.

## Notes

- The config file is generated by Ansible at deploy time. Direct edits on the Pi will be overwritten on the next deployment.
- The file is written with `0600` permissions so only root can read it.
- All timing values may need tuning depending on your display model and how quickly it responds to CEC commands.
